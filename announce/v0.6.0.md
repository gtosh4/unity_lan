**UnityLAN v0.6.0** — named services, real HTTPS, and a mesh for your own machines alone.

**Added**
- **Give a port a name people can remember.** `mc.alice.unity.internal` instead of an address and a port number — type it into a game's server browser, a browser, an SSH command. `ctl service add mc 25565`, or the app's new **Services** tab, which shows what everyone else runs too. A service is an exposed port with a name, so it inherits the scoping you had: one offered to a single network is invisible to everyone else. Names travel device-to-device over the tunnel, so they survive a coordinator outage; allow 30s for a new one to spread.
- **A service that's a website can serve real HTTPS.** Add `--web` and `jellyfin.alice.mesh.unitylan.com` gets a publicly-trusted certificate — no warning page, no root certificate to install anywhere. A new `unitylan-proxy` terminates TLS for you: run Jellyfin on plain HTTP as always. It's a separate unprivileged process — parsing web requests isn't a job for a daemon holding your WireGuard keys — and needs no configuring.
- **Per-device certificates** for anything you'd rather serve yourself: `ctl cert on`, and the device obtains and renews one covering its own name and everything one label below it. The private key never leaves your machine. Issuing publishes that name to public certificate-transparency logs permanently, so it's off by default. Each device gets its own slice of the weekly allowance, so one looping device can't lock everyone out.
- **UnityLAN for just your own machines**, without joining or running a Discord server. Log in, install on a second device, and the two find each other. Previously an account with no role got no address at all.

**Changed — read first**
- **There is no "everyone" scope any more.** `ctl expose` / `ctl service add` require `--net <network>` or `--own-devices` instead of defaulting to every peer you mesh with. **This breaks two things, loudly:** an `expose` entry in `engine.toml` with no `net` or `own_devices` is refused at load and the daemon won't start; `ctl expose <port>` with no scope now errors. Both meant "every peer" — read them as a question: which network was that for? Nothing already open changes.
- Your mesh hostname now comes from your **global Discord username**, not your per-server nickname, and is kept once assigned. If the two differ, expect it to change once. Device names are unaffected.
- Coordinators now **reject** an enrolling device that can't prove it holds the key it registers (observe-only since v0.4.1).

**Fixed**
- **Windows: an update no longer leaves the engine stopped.** The helper that restarts the service was killed the instant the old engine exited, so the update finished and nothing brought the VPN back until a reboot or a manual `sc start`. It now outlives the engine it replaces.
- Certificate names resolve on the machine you type them into — only `.unity.internal` was routed to the mesh, so the HTTPS name went to public DNS and failed. HTTPS also comes up on a packaged install now: the proxy was losing the group membership that reads the certificate key.
- Peers behind strict NATs connect through a relay instead of sitting unreachable — the coordinator was discarding notifications aimed at a peer between check-ins. NAT traversal converges faster too.
- A fresh install no longer comes up with a dead control socket.

**Security**
- The TLS proxy can no longer drive the engine: read-only endpoint, and it no longer inherits the daemon's environment.
- Two members can no longer share one hostname — sanitising folded distinct Discord accounts together, and whoever connected last won.
- A service you can't reach is now indistinguishable from one that doesn't exist.
- Logging out removes your HTTPS certificate and its private key.

Operators: upgrade the coordinator **before** clients; see `docs/coordinator-setup.md` for `[dns]`.
