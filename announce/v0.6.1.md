**UnityLAN v0.6.1** — the HTTPS that v0.6.0 promised, actually serving.

**Fixed**
- **HTTPS for web services works on a packaged Linux install.** In v0.6.0 you could name a service `--web`, turn certificates on, watch a real publicly-trusted certificate arrive — and then nothing served it. The TLS proxy could not start on *any* packaged install, and all it said was `Operation not permitted`. Three independent reasons, all fixed here. If you tried `--web` in v0.6.0 and gave up, try again.
- **The proxy is no longer a separate binary.** It was installed where the engine didn't look; an update would replace an existing copy but never place a missing one; a source build had none at all. Every one of those surfaced only as "HTTPS silently doesn't work". The engine now runs the proxy as *itself*, re-executed unprivileged under its own account — so it is always present, and can never be a version out of step with the engine supervising it. The isolation is unchanged: separate process, separate uid, read-only control socket, no capabilities.
- **The service unit grants the three capabilities this needs.** Dropping the proxy to its own account needs `CAP_SETUID`/`CAP_SETGID`, and handing it the certificate key needs `CAP_CHOWN` — without them the kernel refuses even though the daemon runs as root. That's what the bare `Operation not permitted` was.
- **A certificate key whose group grant failed is repaired at the next start.** Previously only issuance did it, so a grant that failed once left a valid certificate the proxy couldn't read for its whole 60-day life.
- **When the kernel refuses one of these, the engine now names the missing capability** and the setting to add, instead of an errno that points at nothing.

**Added**
- **Web services are clickable in the app.** A service marked as a website opens in your browser when you click its name — in your own list and in everyone else's. Web names are shown in link blue; anything you'd dial with its own client stays plain text.

**Changed**
- `[proxy] binary` is gone from the config. There is no separate binary to point at; the setting is ignored if you leave it there.

**Upgrading — Linux, please read**
An auto-update replaces binaries but **not** the systemd unit, so a host that auto-updates from v0.6.0 arrives with the new engine and the old capability set — and HTTPS still won't work. Upgrade the package (`apt`/`dnf`) to pick up the fixed unit. Everything else about the update is unchanged, and nothing here touches the mesh itself: tunnels, names and scoping all behave as they did.

If you added capabilities or copied a proxy binary by hand to work around this in v0.6.0, you can drop both once you're on the packaged v0.6.1.

**Windows**
Unaffected by the Linux packaging fixes. The proxy's Windows path is now registered as the engine's own image rather than a second executable; it remains untested on that platform, as it was in v0.6.0.
