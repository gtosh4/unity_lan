**UnityLAN v0.5.0** — reconnect, LAN paths, and a tighter update trust root.

**Security**
- Auto-updates now go **only** over the dedicated offline release key — the guild-signed fallback is gone, closing a path from one leaked guild key to root-level code on every member's machine. **Operators mid-upgrade: keep serving the guild-signed manifest until every device is on this release** (`docs/release-signing.md`). Development builds no longer self-update.
- A replayed high-version update manifest can no longer freeze a device's auto-updates by pushing its rollback floor past every real release.
- Defense-in-depth hardening across the engine: bounded trust-anchor chains and update artifacts, a stricter resolver, owner-only state dir, and control-socket timeouts/limits.
- The coordinator no longer lets an account bloat its database with repeated interactive-login bindings (now capped per account).

**Fixed**
- Coordinator comes back online in ~2 min instead of staying greyed out for up to 15, via long-poll keepalives.
- Restarting an engine no longer 429-strands it (and shows the coordinator offline) for up to 15 min — a device's newest request now takes the slot.
- Two devices on the same network now use the direct local path even when the router's hairpin only *intermittently* works, gated on an authenticated check so spoofed addresses are never adopted.
- Packaged Linux installs regain peer latency and LAN-path confirmation (`CAP_NET_RAW` now granted).
- The GUI can again reach an engine using the default control-socket location.
- The update prompt no longer stays hidden when a staged release is ready but the coordinator hasn't upgraded its own binary.
- Peer-direct attestation refresh no longer stops serving after a peer goes offline.

**Changed**
- A busy coordinator makes far fewer Discord calls on a cold cache — simultaneous per-guild lookups are now coalesced into one.
