**UnityLAN v0.6.2** — a shared coordinator that stays fast as it fills, logs that stop growing, and a stop that stops.

**Fixed**
- **A busy coordinator no longer gets slower every time an unrelated community joins it.** Working out which networks you belong to meant asking Discord about you once for *every* community registered on that coordinator — not just the ones you're in — on every device, every fifteen minutes. Discord caps how fast anyone may ask, so the coordinator burned its whole allowance re-learning that you are not a member of servers you've never heard of, and everyone's peer list took longer to arrive as more communities signed up. It now remembers a "not a member" answer for one refresh cycle and drops it the moment someone actually joins, so a join still takes effect immediately. Self-hosted with one community: nothing changes. On a shared one the difference is large — a 25-community deployment answers a refresh in about a second where it previously took the better part of a minute.
- **No log file grows forever any more.** Every log this writes — the Windows service's, and any `log_file` you set on either platform — was a plain append that grew for the life of the install, with nothing ever pruning it. They now roll daily and keep a week: long enough to still hold a failure you're only now getting round to reporting, bounded so a flapping peer can't quietly fill the disk of a box nobody logs into. The name gains the day it covers, so `engine.log` is written as `engine.<date>.log`. Linux packaged installs are unaffected — the journal has always held this, and rotates already.
- **`log_file` now works for the Windows service.** It was read only on the command line the service never takes, so setting it did nothing and the service logged beside its executable regardless. A new install keeps its log with the rest of the engine's state, in `C:\ProgramData\UnityLAN`. Upgrading keeps the config you have, so the log stays where it was — still there, still rotated.
- **Stopping the engine no longer hangs.** A stop had two ways to stall. If the engine was between attempts to reach an unreachable coordinator, it waited out the retry backoff — up to 45 seconds of a daemon with nothing left to do. And if removing the WireGuard interface got stuck (a known wedge inside the userspace WireGuard library), it never finished at all: `systemctl stop` sat through its whole timeout before killing the engine, and stopping it by hand left it running with the interface still up. A stop now interrupts the backoff immediately, and teardown gives itself ten seconds before exiting regardless — after the firewall, DNS and mesh presence have already been put back, so the part it may cut short is the part the next start cleans up.

**Added**
- **Copy a service's address from the app.** Every service — yours and everyone else's — has a copy button that puts the address you'd actually paste on the clipboard: the `https://` name for a website, `name:port` for anything a client dials. Hover to see what it hands over. Reading a hostname off the screen and retyping it into a server browser was the one part of naming a port that the name didn't help with.

**Changed**
- **The Services tab leads with what the mesh is serving.** Finding someone else's Jellyfin or game server is the everyday reason to open that tab; exposing one of your own is something you do once and rarely revisit — yet your own list and its row of input boxes sat on top, pushing everyone else's services down the window. Your services moved below the mesh list, and adding one is now a dialog off an "expose a service" button, with a labelled field per choice instead of four placeholder-only boxes crammed into a line.

**Upgrading**
Nothing here changes the wire protocol, the trust model, or how tunnels form. If you run a coordinator hosting more than a couple of communities, take it there first.
